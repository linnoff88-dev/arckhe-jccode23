🌐 Qué es GitHub Pages

Alojamiento gratuito de sitios estáticos directamente desde tu repositorio

🎯 GitHub Pages en 30 segundos

Tienes archivos HTML/CSS/JS en GitHub. Pages los sirve como un sitio público con URL propia, HTTPS automático y CDN global — sin pagar nada, sin configurar un servidor.

Push → build automático → CDN → sitio en línea. Todo el proceso lo gestiona GitHub.

✓ Qué incluye Pages (gratis)

  • ✓HTTPS automático (Let's Encrypt)
  • ✓CDN global (Fastly)
  • ✓URL usuario.github.io/repo
  • ✓Deploys automáticos con cada push

✗ Qué NO hace Pages

  • ✗Backend/servidor (solo estático)
  • ✗Base de datos
  • ✗Node.js, PHP, Python en ejecución
  • ✗Repositorios privados (plan gratuito)

⚙️ Activar Pages

Branch/carpeta o GitHub Actions — 3 caminos, 1 resultado

A

Mediante la interfaz web (más fácil)

  1. Abre el repositorio en GitHub
  2. Ve a Settings → Pages
  3. En "Source", selecciona la branch (main) y la carpeta (/ o /docs)
  4. Haz clic en Save — espera 1-5 minutos
B

Mediante gh CLI (rápido y automático)

# Ativar Pages na branch main, pasta raiz
$ gh api repos/:owner/:repo/pages \
  -X POST \
  -f source='{"branch":"main","path":"/"}'

# Verificar status
$ gh api repos/:owner/:repo/pages | jq '.status, .html_url'
C

Branch gh-pages dedicada

# Criar e fazer push para branch gh-pages
$ git checkout --orphan gh-pages
$ git rm -rf .              # limpa a branch
$ cp -r dist/* .             # copia os arquivos de build
$ git add . && git commit -m "deploy: v1.0"
$ git push -u origin gh-pages

💡 ¿Qué método usar?

Para proyectos simples (HTML/CSS puro): rama main + carpeta /. Para proyectos con build (React, Vue, etc.): GitHub Actions hace el build y publica automáticamente. La carpeta /docs es útil cuando el código y la documentación están en el mismo repo.

🌍 Dominio personalizado y CNAME

meusite.com en vez de usuario.github.io — profesionalismo por ~R$50/año

1

Crear el archivo CNAME en el repo

# Na raiz do branch de Pages:
$ echo "meusite.com" > CNAME
$ git add CNAME && git commit -m "chore: adiciona domínio customizado"
$ git push
2

Configurar DNS en el registrador

Para www (subdominio):

Tipo: CNAME
Nome: www
Valor: usuario.github.io

Para dominio raíz (raíz):

Tipo: A  |  Nome: @  |  Valor: 185.199.108.153
Tipo: A  |  Nome: @  |  Valor: 185.199.109.153
Tipo: A  |  Nome: @  |  Valor: 185.199.110.153
Tipo: A  |  Nome: @  |  Valor: 185.199.111.153
3

Activar HTTPS y verificar

En Settings → Pages, configura el dominio y marca "Enforce HTTPS". Espera a que se propaguen los DNS (hasta 48h).

# Testar propagação DNS
$ dig www.meusite.com CNAME
$ nslookup meusite.com

⏱️ Caché y actualización

¿Por qué no se actualizó el sitio? Entiende y resuélvelo en segundos

🤔 "¡Hice push, pero el sitio no cambió!"

Esto ocurre por una caché de dos capas: (1) el deploy de GitHub Pages tarda entre 1-10 minutos; (2) el navegador almacena los archivos en caché. Espera a que termine la compilación y fuerza la actualización de la página.

✓ Cómo verificar la compilación

  • ✓Pestaña Actions en GitHub: estado del workflow "pages build"
  • ✓gh run list --workflow pages en la terminal
  • ✓gh run watch monitorea en tiempo real
  • ✓Configuración → Pages muestra "Your site is live at..."

🛠️ Forzar la actualización en el navegador

  • →Windows/Linux: Ctrl+Shift+R
  • →macOS: Cmd+Shift+R
  • →DevTools → Network → Disable cache (mientras esté abierto)
  • →Agregar ?v=2 en la URL para probar

✅ Verificar que esté en línea

Confirmar el deploy con comandos reales, sin suposiciones

LISTA DE VERIFICACIÓN POST-DEPLOY
# 1. Confirmar que Pages está ativo
$ gh api repos/:owner/:repo/pages --jq '{status:.status, url:.html_url}'
{"status":"built","url":"https://usuario.github.io/repo/"}

# 2. Testar HTTP status
$ curl -s -o /dev/null -w "%{http_code}" https://usuario.github.io/repo/
200

# 3. Verificar HTTPS redirect
$ curl -I http://usuario.github.io/repo/
HTTP/1.1 301 Moved Permanently
Location: https://usuario.github.io/repo/

# 4. Verificar conteúdo correto
$ curl -s https://usuario.github.io/repo/ | grep ""
<title>Meu Projeto</title>
