2 ⚙️ scripts/aggregate.ts — el corazón del sistema

El archivo más importante de ClaudeOS no es un componente de React: es un script TypeScript que se ejecuta fuera del navegador. Lee fuentes heterogéneas y produce un único JSON que consume el dashboard.

scripts/aggregate.ts — estructura simplificada

💡

El patrón "script → JSON → UI"

Separar la recopilación de datos de la presentación es una de las arquitecturas más resilientes para proyectos personales. El dashboard se puede reconstruir desde cero sin perder datos. El pipeline puede ejecutarse en el cron sin que exista la UI.

3 💤 Skill /dream — auditoría de 24h

La skill /dream es un ejemplo de skill con output estructurado. No responde en prosa: escribe un archivo JSON que el dashboard muestra como tarjetas de acción.

~/.claude/skills/dream/SKILL.md — estructura 
# Skill /dream

## Propósito
Auditar as últimas 24h do stack de IA em 8 buckets de sinal.
Gerar as 4 prescrições de maior impacto em JSON.

## Buckets de sinal
1. Tokens consumidos vs budget diário
2. Projetos mais ativos (por sessão)

4 📜 CLAUDE.md de ClaudeOS — ejemplo real

El CLAUDE.md de ClaudeOS es un ejemplo de instrucciones de nivel de producción. Cada regla tiene una razón clara de existir.

CLAUDE.md — ClaudeOS (Hermes) 
# ClaudeOS (Hermes) — Instruções do agente

## Saudação de onboarding
Bem-vindo ao ClaudeOS! Você está trabalhando no dashboard
pessoal de IA. Antes de qualquer task, leia este arquivo.

## O que é este projeto
Dashboard read-only que consolida dados de Claude Code,
Obsidian, OpenRouter e Pinecone para visualização pessoal.
Stack: Bun + React 19 + TanStack Query + Vite + Tailwind 4
Deploy: Cloudflare Pages (wrangler)

## Regras OBRIGATÓRIAS

### Privacidade
- NUNCA ler ou escrever diretamente em ~/.claude/
  → Dados chegam via scripts/aggregate.ts e src/data/live-data.json
- NUNCA enviar dados do usuário para serviços externos
- Anonimização LIGADA — remove PII de outputs
- Sem telemetria — sem analytics, sem tracking

### Arquitetura
- Dashboard é READ-ONLY — NUNCA modificar fontes de dados
- Código novo vai em src/ — scripts de dados vão em scripts/
- Não criar arquivos na raiz do projeto

### Segurança
- API keys SEMPRE via variáveis de ambiente (.env)
- .env está no .gitignore — nunca commit

## Estrutura do projeto
src/
  components/   → UI React
  data/         → live-data.json (gerado, não editado)
scripts/
  aggregate.ts  → coleta dados das fontes
  setup.ts      → setup inicial (roda uma vez)

🔍 Por qué existe cada regla

Nunca leas ~/.claude directamente: evita el acceso inadvertido a conversaciones privadas
Read-only enforcement: evita errores que corrompen las fuentes de datos
Sin telemetría: proyecto personal — ningún dato sale del dispositivo

🧩 Patrón reutilizable

• Saludo de onboarding = contexto inmediato

• Reglas por categoría (privacidad, arquitectura, seguridad)

• Justificación inline para cada restricción crítica

• Mapa de carpetas con propósito explícito
