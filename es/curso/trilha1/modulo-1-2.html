🔄 El bucle del agente

Claude Code no lee tu mensaje y responde de inmediato. Ejecuta un bucle de razonamiento y acción — el patrón ReAct — que se repite hasta completar la tarea o hasta que ya no puedas avanzar más.

🔄 ReAct en detalle

ReAct (Reasoning + Acting) es el patrón de agente más común. El modelo razona sobre el problema, elige una herramienta, la ejecuta, observa el resultado y vuelve a razonar; repite el proceso hasta terminar.

  • •Pensar: "Necesito saber qué hay en src/auth.ts antes de editar"
  • •Actuar: Llama Read("src/auth.ts")
  • •Observar: Recibe el contenido del archivo
  • •Pensar: "Necesito agregar la función en la línea 42..."

🛠️ Las herramientas del agente

Claude Code tiene un conjunto de herramientas nativas que usas en cada ciclo. Cada herramienta tiene un costo en tokens y requiere permisos específicos. Conocerlas es conocer las manos del agente.

✓ Herramientas de lectura (seguras)

  • Read— lee el contenido de un archivo
  • Glob— lista archivos según un patrón glob
  • Grep— busca texto/expresiones regulares en archivos
  • LS— lista directorios y estructura

⚠️ Herramientas de escritura (requieren cuidado)

  • Editar— modifica fragmentos de un archivo
  • Write— crea o sobrescribe un archivo
  • Bash— ejecuta cualquier comando de shell
  • TodoWrite— administra una lista interna de tareas

💡 Consejo: observa las herramientas en los logs

Cada herramienta aparece en los logs con un prefijo ●. Aprende a leer estos logs: muestran exactamente qué está haciendo el agente y en qué archivo. Es lo más parecido a «ver el pensamiento del agente».

📋 Cómo planifica

Antes de actuar, Claude Code hace una planificación implícita: divide el problema en pasos, identifica qué archivos necesita leer primero y elige la secuencia de herramientas más eficiente.

Cómo aborda el agente «Agrega pruebas al módulo auth»

1

Exploración — "¿qué existe?"

Usa Glob("**/*.test.ts") e Glob("src/auth/**") para mapear el proyecto.

Necesita entender la estructura antes de crear cualquier archivo.

2

Lectura: "¿qué hace?"

Lee src/auth/index.ts, src/auth/utils.ts y pruebas existentes como referencia.

Sin leer el código, no sabes qué probar.

3

Escritura — «crea las pruebas»

Usa Write("src/auth/auth.test.ts", ...) con el contenido generado.

Sigue el patrón de las pruebas existentes, respetando el framework detectado.

4

Validación — "¿funciona?"

Se ejecuta Bash("npm test src/auth") y corrige fallas.

Nunca entregues código sin probar: el ciclo de feedback es automático.

📋 Plan explícito frente a implícito

De forma predeterminada, la planificación es interna (invisible). Para tareas complejas, puedes pedirle al agente que cree un plan antes de actuar: "Antes de implementar, enumera los pasos que vas a seguir". Esto reduce los errores en tareas largas.

🛡️ Cuando solicita permiso

Claude Code tiene un sistema de permisos granulares. Opera de forma autónoma en las acciones permitidas, pero se detiene y pide confirmación antes de realizar acciones que pueden causar daños irreversibles.

✓ Lo hace sin preguntar

  • ✓Leer cualquier archivo
  • ✓Editar archivos de código (si están en la allowlist)
  • ✓Ejecutar npm test, git status, git diff
  • ✓Crear archivos nuevos

⚠️ Pide confirmación

  • ⚠️Eliminar archivos o carpetas
  • ⚠️Comandos destructivos (rm -rf, drop table)
  • ⚠️Push a repositorios remotos
  • ⚠️Instalar dependencias globales

⚙️ Configurar permisos en settings.json

// .claude/settings.json
{
"permissions": {
"allow": ["Bash(npm test:*)","Bash(git commit:*)"],
"deny": ["Bash(rm -rf:*)"]
}
}

💡 Consejo: configura la allowlist al inicio

Pasar las primeras horas pidiéndole permiso al agente para cada npm test es irritante. Configura el settings.json del proyecto en las primeras sesiones para los comandos que usas con frecuencia.

🚧 Límites del agente

Conocer los límites reales del agente es tan importante como conocer sus capacidades. Las expectativas equivocadas generan frustración y resultados mediocres.

📊 Qué no hace Claude Code de forma nativa

  • 1.Sin memoria entre sesiones: cada nueva sesión empieza desde cero (sin CLAUDE.md)
  • 2.Sin acceso a Internet: no consulta documentación en línea sin una herramienta adicional
  • 3.Sin GUI: no hace clic en botones, no navega en aplicaciones gráficas
  • 4.Sin visión: no lee imágenes, PDF visuales ni capturas de pantalla
  • 5.Sin ejecución en paralelo: una tarea a la vez en la misma sesión

✓ Resolverlo con CLAUDE.md

  • ✓Crear un archivo CLAUDE.md en el proyecto con instrucciones persistentes
  • ✓Incluir el contexto del proyecto, las reglas de código y las preferencias
  • ✓El agente lee el archivo automáticamente al iniciar

✗ Límites reales (sin hack)

  • ✗No recuerda conversaciones de sesiones anteriores
  • ✗No monitorea archivos en tiempo real
  • ✗No programa tareas automáticas

🔍 Observando al agente trabajar

Claude Code es transparente: cada acción aparece en la terminal en tiempo real. Aprender a leer esos logs es una habilidad que acelera tu aprendizaje exponencialmente.

💻 Registro de una sesión típica

> Agrega una función de hash de contraseña en auth.ts
● Bash: find . -name "*.ts" -path "*/auth/*"
● Read: src/auth/auth.ts (342 lines)
● Read: src/auth/types.ts (89 lines)
● Bash: grep -r "bcrypt\|argon2\|crypto" package.json
● Edit: src/auth/auth.ts
● Bash: npx tsc --noEmit src/auth/auth.ts
✓ Función hashPassword añadida. Usando crypto.pbkdf2...

💡 Qué significa cada línea del log

  • Bash: find... — exploración de la estructura del proyecto
  • Read: archivo (N lines) — leyendo N líneas de contexto
  • Bash: grep... — buscando dependencias disponibles
  • Edit: archivo — modificando el archivo
  • Bash: npx tsc... — verificando errores de compilación
