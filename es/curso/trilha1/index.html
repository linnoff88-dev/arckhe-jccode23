🧭 Qué es Claude Code

Entiende qué diferencia a un agente de IA de un chatbot y por qué Claude Code vive en el terminal.

Qué es:

Un agente es un programa que percibe el entorno, toma decisiones y actúa de forma autónoma para alcanzar un objetivo, a diferencia de un chatbot que solo responde preguntas.

Por qué aprender:

Entender esta diferencia es fundamental para saber qué esperar de Claude Code y cómo pedir tareas de forma eficiente.

Conceptos clave:

Percepción → Decisión → Acción; ciclo autónomo; objetivo frente a respuesta única; contexto persistente.

Qué es:

La terminal es la interfaz de texto que da acceso directo al sistema operativo: archivos, procesos, red. Es donde el agente ejecuta comandos reales.

Por qué aprender:

Las interfaces gráficas son lentas y difíciles de automatizar. En la terminal, Claude Code puede leer, escribir, ejecutar y buscar en segundos.

Conceptos clave:

Shell, stdin/stdout, pipe, permisos de archivo, PATH, proceso hijo.

Qué es:

Claude Code usa herramientas concretas: Read (lee archivos), Edit (modifica archivos), Bash (ejecuta comandos), Search (busca patrones en el código).

Por qué aprender:

Saber qué herramientas existen ayuda a entender qué puede y qué no puede hacer el agente en cada tarea.

Conceptos clave:

Read, Edit, Write, Bash, Glob, Grep — las herramientas nativas de Claude Code.

Qué es:

Refactorizar código, crear funciones, escribir pruebas, migrar APIs, corregir errores, generar documentación — todo sin salir del terminal.

Por qué aprender:

Delimitar el alcance de uso aumenta la efectividad. Saber «dónde destaca el agente» ahorra tiempo y evita frustraciones.

Conceptos clave:

Tareas de código, automatización de repositorios, CI/CD, generación de boilerplate, análisis de logs.

Qué es:

Un chatbot responde texto. Un agente ejecuta acciones en el mundo real: crea archivos, ejecuta pruebas, hace commits. Claude Code es un agente.

Por qué aprender:

Cambiar el enfoque mental de "preguntar" a "delegar tareas" transforma la forma de usar la herramienta.

Conceptos clave:

Acción vs. respuesta; efecto secundario; permiso de ejecución; autonomía controlada.

Qué es:

El primer contacto: abrir la terminal, escribir claude, pedir una tarea sencilla y observar cómo trabaja el agente paso a paso.

Por qué aprender:

Ver al agente en acción — con las herramientas apareciendo en tiempo real — es la mejor forma de asimilar el concepto.

Conceptos clave:

Sesión interactiva, modo headless, claude --help, primera tarea delegada.

🧠 Cómo piensa el agente

Descubre el ciclo interno del agente: cómo planifica, elige herramientas y decide cuándo pedir permiso.

Qué es:

El agente ejecuta un ciclo continuo: Pensar (razonar sobre qué hacer), Usar herramienta (acción en el mundo real), Observar (leer el resultado) y repetir.

Por qué aprender:

Entender el ciclo ayuda a formular mejores tareas y a saber por qué el agente hace ciertas preguntas o toma ciertas decisiones.

Conceptos clave:

Bucle ReAct, "chain of thought", observación del entorno, iteración hasta completar.

Qué es:

Las herramientas son las «manos» del agente: Read (lee archivos), Edit (edita archivos), Bash (ejecuta comandos), Glob (lista archivos), Grep (busca texto).

Por qué aprender:

Cada herramienta tiene costos, permisos y alcances diferentes. Conocerlas permite entender los logs y optimizar el flujo.

Conceptos clave:

Llamada a herramienta, resultado de herramienta, permiso explícito vs. implícito, costo en tokens por herramienta.

Qué es:

Antes de actuar, el agente razona internamente: divide el problema en pasos, identifica dependencias y elige la herramienta adecuada para cada etapa.

Por qué aprender:

Dar suficiente contexto en la tarea permite que el plan sea más preciso y reduce idas y vueltas innecesarias.

Conceptos clave:

Descomposición de tareas, plan explícito vs. implícito, bloc de notas interno, seguimiento del progreso.

Qué es:

El agente pide confirmación antes de realizar acciones destructivas (eliminar archivos, ejecutar comandos peligrosos) o cuando no tiene suficiente contexto.

Por qué aprender:

Saber cuándo el agente hará una pausa y pedirá ayuda evita sorpresas y ayuda a configurar correctamente los permisos en settings.json.

Conceptos clave:

allowlist, denylist, confirmación interactiva, modo autónomo, --dangerously-skip-permissions.

Qué es:

El agente no navega por sitios, no hace clic en interfaces gráficas (sin plugins), no tiene memoria entre sesiones de forma predeterminada y no tiene acceso a Internet sin herramientas externas.

Por qué aprender:

Conocer los límites evita expectativas equivocadas y ayuda a complementar con otras herramientas cuando sea necesario.

Conceptos clave:

Sin memoria persistente nativa, sin acceso a GUI, con sandboxing y alcance limitado al proyecto local.

Qué es:

Durante la ejecución, Claude Code muestra cada herramienta que se invoca, lo que se leyó y lo que se modificó — el registro visible del razonamiento en tiempo real.

Por qué aprender:

Leer los logs ayuda a entender las decisiones, detectar errores antes y confiar más en lo que hace el agente.

Conceptos clave:

Salida verbose, registro de herramientas, razonamiento explícito, verificación humana, interrupción segura (Ctrl+C).

🪟 Contexto, tokens y ventana

Entiende cómo el agente "recuerda" las cosas, por qué esa memoria tiene un límite y cómo no desperdiciarla.

Qué es:

El contexto es todo lo que el modelo "sabe" en ese momento: la conversación, los archivos leídos y el resultado de las herramientas. Es la memoria de trabajo activa de la sesión.

Por qué aprender:

Si no entiendes el contexto, no sabrás por qué el agente «olvidó» algo o por qué sus respuestas se volvieron extrañas al final de la sesión.

Conceptos clave:

Prompt, historial de conversación, resultados de herramientas en el contexto, CLAUDE.md como contexto persistente.

Qué es:

Los tokens son fragmentos de texto (≈ 4 caracteres en inglés, ≈ 3 en pt-BR). Cada palabra se convierte en 1-3 tokens. Los modelos procesan y cobran por tokens.

Por qué aprender:

Entender los tokens ayuda a estimar costos, controlar el uso de la ventana y evitar superar el límite que degrada las respuestas.

Conceptos clave:

Token de entrada, token de salida, tokenizer, costo por 1M tokens, longitud del archivo en tokens.

Qué es:

La ventana de contexto es el límite máximo de tokens que el modelo procesa de una vez. Claude 3 Sonnet tiene 200K tokens — unas 500 páginas de texto.

Por qué aprender:

Cuando la ventana se llena, el agente empieza a «olvidar» partes de la conversación o el sistema trunca el contexto automáticamente.

Conceptos clave:

200K tokens, truncamiento automático, degradación del rendimiento, ventana deslizante.

Qué es:

El contexto se llena por estos motivos: archivos grandes leídos completos, historial extenso, respuestas verbosas y muchas llamadas a herramientas acumuladas en la misma sesión.

Por qué aprender:

Identificar al culpable permite actuar: dividir sesiones, usar /clear o cambiar la estrategia para leer archivos.

Conceptos clave:

Archivo grande, historial extenso, resultados de herramientas acumulados, lectura innecesaria de archivos binarios.

Qué es:

El comando /compact reanuda la conversación anterior y libera espacio en la ventana. Claude Code también compacta automáticamente cuando es necesario.

Por qué aprender:

Saber cuándo y cómo compactar evita perder contexto crítico y mantiene la eficacia del agente en sesiones largas.

Conceptos clave:

/compact, /clear, tipos en

Qué es:

Prácticas como usar CLAUDE.md para instrucciones fijas, dividir las tareas grandes en sesiones más pequeñas y evitar leer archivos innecesarios ahorran tokens y mejoran la calidad.

Por qué aprender:

Un contexto conciso significa respuestas más precisas, menor costo y sesiones más largas antes de la degradación.

Conceptos clave:

CLAUDE.md, sesiones cortas y enfocadas, lectura selectiva, evita copiar código completo en los mensajes.

⌨️ Terminal y CLI para principiantes

De cero a la terminal: carpetas, rutas, comandos esenciales y seguridad básica para quienes nunca han usado la terminal.

Qué es:

La terminal es un programa que interpreta comandos de texto. En Mac: Terminal o iTerm2. En Windows: PowerShell o WSL. En Linux: cualquier emulador.

Por qué aprender:

Claude Code solo funciona en la terminal. Sin saber abrir y usar la terminal, ni siquiera es posible iniciar el agente.

Conceptos clave:

Shell (bash/zsh), prompt ($), emulador de terminal, stdin/stdout, código de salida 0 = éxito.

Qué es:

El sistema de archivos es un árbol. Ruta absoluta: /home/user/projeto. Ruta relativa: ./src. El punto de partida es el directorio actual.

Por qué aprender:

Claude Code opera en el directorio desde el que lo inicias. Entender las rutas es esencial para indicar al agente cuáles son los archivos correctos.

Conceptos clave:

Raíz (/), home (~), ruta absoluta, ruta relativa, . (actual), .. (padre).

Qué es:

cd (cambiar de carpeta), ls (listar), mkdir (crear carpeta), pwd (dónde estoy), cat (ver archivo), cp/mv/rm.

Por qué aprender:

Claude Code usa estos comandos en casi todas las tareas. Reconocerlos en los logs ayuda a seguir lo que está haciendo el agente.

Conceptos clave:

cd, ls -la, mkdir -p, pwd, cat, cp, mv, rm -rf (¡cuidado!), man (ayuda).

Qué es:

CLI (Command-Line Interface) es un programa que controlas mediante texto en la terminal: git, npm, python, claude son CLIs.

Por qué aprender:

Claude Code ES una CLI. Entender cómo funcionan las CLI (flags, subcomandos, --help) te ayuda a usar cualquier herramienta de línea de comandos.

Conceptos clave:

Flags (--flag), argumentos posicionales, subcomandos, --help, código de retorno.

Qué es:

Los gestores de paquetes instalan CLIs: npm install -g @anthropic-ai/claude-code (Node), brew install (Mac), apt install (Linux).

Por qué aprender:

Instalar Claude Code es el primer paso práctico. Entender cómo funcionan los gestores de paquetes evita errores de instalación.

Conceptos clave:

npm, Node.js, PATH, versión global vs. local, which claude, actualización.

Qué es:

Nunca ejecutes comandos copiados de internet sin entender qué hacen. rm -rf /, curl | bash sin verificar, y sudo lo innecesario son riesgos reales.

Por qué aprender:

La terminal tiene poder real sobre el sistema. Un comando incorrecto puede borrar archivos, exponer credenciales o instalar malware.

Conceptos clave:

Leer antes de ejecutar, usar sudo con moderación, proteger los secretos en las variables de entorno y agregar .env a .gitignore.
