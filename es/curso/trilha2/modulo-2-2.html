🔐 Flujo de inicio de sesión detallado

Claude Code usa OAuth2 vía browser como método principal. Las credenciales están en ~/.claude/ y son válidas hasta que expiran (por lo general, semanas).

Comandos de autenticación

# Autenticar pela primeira vez (abre browser)
claude

# Verificar status de autenticação
claude --status

# Forçar reautenticação
claude --logout
claude

# Ver onde as credenciais estão salvas
ls ~/.claude/

# Autenticar em ambiente sem browser (API key)
export ANTHROPIC_API_KEY="sk-ant-..."
claude

💡 ¿El token vence? No te preocupes

Cuando el token OAuth vence, Claude Code te avisa en la siguiente sesión y vuelve a abrir el navegador automáticamente. El flujo es idéntico al del primer inicio de sesión. Tus configuraciones e historial no se ven afectados.

💳 API key vs. suscripción

Dos formas de pagar por el uso. La elección correcta depende de tu volumen de uso — uso esporádico favorece la API key, uso diario intenso favorece la suscripción Claude Max.

🔑 API Key (pago por uso)

  • •Pagas por token consumido (input + output)
  • •Ideal para uso ocasional o scripts automatizados
  • •Control granular de costos
  • •Límites de rate por minuto/día
  • •Variable: ANTHROPIC_API_KEY

📋 Claude Max (suscripción)

  • •Cuota fija mensual generosa
  • •Mejor relación costo-beneficio para uso diario (8h/día)
  • •Acceso a los modelos más recientes
  • •Inicio de sesión mediante OAuth en el navegador (sin API key)
  • •La cuota se restablece mensualmente

Usar una clave de API en Claude Code

# Opção 1: variável de ambiente (sessão atual)
export ANTHROPIC_API_KEY="sk-ant-api03-..."
claude

# Opção 2: persistir no .bashrc ou .zshrc
echo 'export ANTHROPIC_API_KEY="sk-ant-api03-..."' >> ~/.bashrc
source ~/.bashrc

# Opção 3: informar na autenticação interativa
claude
# Escolher opção 2 (Enter API key manually)
# Colar a chave quando solicitado

# Verificar qual método está sendo usado
claude --status

⚠️ Nunca expongas tu API key

No hagas git add .env o commit de archivos con ANTHROPIC_API_KEY. Añade a .gitignore. Anthropic detecta y revoca automáticamente las claves expuestas en repos públicos, pero el daño puede estar hecho.

💬 El prompt interactivo (REPL)

El REPL de Claude Code acepta lenguaje natural, comandos slash y referencias a archivos con @. Entender estos tres inputs multiplica tu productividad.

✓ Qué puedes escribir

  • ✓Solicitudes en portugués: "Crea un servidor Express básico"
  • ✓Referencia a archivos: "Refactoriza @src/api.js"
  • ✓Comandos slash: /help, /clear, /status
  • ✓Mensajes largos: Shift+Enter para una nueva línea
  • ✓Contexto acumulativo: Claude recuerda la conversación

✗ Evitar en el REPL

  • ✗Solicitudes vagas sin contexto: "mejora el código"
  • ✗Tareas muy grandes en un solo prompt
  • ✗Pegar secretos/tokens directamente en el chat
  • ✗Ignorar las confirmaciones de permisos

Comandos slash más útiles

/help          # Lista todos os comandos disponíveis
/clear         # Limpa o contexto da conversa atual
/status        # Mostra modelo, uso de contexto, autenticação
/exit          # Sair do REPL (ou Ctrl+C)
/mcp           # Lista servidores MCP conectados
/init          # Gera CLAUDE.md para o projeto atual
/cost          # Mostra tokens usados na sessão

💡 Usa @ para hacer referencia a archivos

Escribir @ en el REPL se abre el autocompletado de archivos del proyecto. Puedes hacer referencia a un archivo específico sin pegar el contenido manualmente:

> Explique o que faz @src/auth/middleware.js e sugira melhorias

⌨️ Primeros comandos reales

Ponte manos a la obra ahora. Estas son las primeras solicitudes que le harás a Claude Code; cada una demuestra una capacidad diferente.

1. Crear un archivo

> Crie um arquivo README.md para este projeto com seções básicas

Claude pide confirmación antes de escribir → tú apruebas → archivo creado

2. Explorar el proyecto

> O que faz este projeto? Leia os arquivos principais e me explique

La lectura es segura: no requiere confirmación. Claude lee y resume el codebase

3. Ejecutar comando

> Rode os testes e me diga se todos passaram

Claude pide permiso para ejecutar bash → tú apruebas → ejecuta e informa

4. Refactorizar código

> Refatore @src/index.js para usar async/await em vez de callbacks

Claude muestra el diff antes de aplicarlo → tú revisas → apruebas o cancelas

📊 Bucle de confirmación

Toda acción que modifica archivos o ejecuta comandos pasa por una confirmación. Este es el mecanismo central de seguridad:

  • y → aprobar y ejecutar
  • n → rechazar (Claude intenta un enfoque alternativo)
  • a → aprobar todas las acciones pendientes de esta tarea
  • Ctrl+C → cancelar tarea actual

🔄 Salir, retomar y administrar sesiones

Las sesiones de Claude Code tienen un contexto que se puede retomar. Entender el ciclo de vida de la sesión evita perder contexto importante a mitad de un proyecto.

Comandos de sesión

# Sair do REPL
/exit          # ou Ctrl+C duas vezes

# Retomar sessão anterior do mesmo diretório
claude --resume

# Ver sessões disponíveis
claude --list-sessions

# Iniciar sessão sem histórico (limpa)
claude --no-resume

# Usar claude sem REPL (modo print, para scripts)
claude --print "Gere um script Python para ordenar arquivos por data"

# Passar contexto via stdin
cat meu_arquivo.py | claude --print "Explique este código"

✓ Buenas prácticas de sesión

  • ✓Usa /clear cuando cambies de tarea
  • ✓Retoma con --resume para continuar con los bugs
  • ✓Usa /status para ver los tokens usados

💡 Contexto y tokens

Cada sesión consume tokens de contexto. Las sesiones largas se vuelven más costosas y lentas. Usa /clear para restablecer cuando el contexto ya no sea necesario.
