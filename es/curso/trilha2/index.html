⚙️ Instalar Claude Code

Requisitos, instalación mediante npm/bun, verificación, actualización y solución de los errores más comunes en cualquier OS.

Qué es:

Node.js v18+ (o Bun), terminal con soporte para colores y acceso a internet para la autenticación inicial.

Por qué aprender:

Sin el entorno adecuado, la instalación falla silenciosamente. Verificarlo antes te ahorra 30 min de depuración.

Conceptos clave:

Node.js LTS, verifica con node -v, npm v9+ o Bun v1+, compatibilidad con macOS/Linux/WSL2.

Qué es:

Un solo comando instala Claude Code globalmente: npm install -g @anthropic-ai/claude-code.

Por qué aprender:

La instalación global hace que el comando claude disponible en cualquier directorio del sistema.

Conceptos clave:

Flag -g (global), permisos de carpeta de npm, alternativa con Bun: bun install -g.

Qué es:

Ejecutar claude --version e claude --help para confirmar que el binario está en el PATH.

Por qué aprender:

Detecta errores de PATH antes de perder tiempo con la autenticación. «command not found» tiene una solución sencilla.

Conceptos clave:

PATH del sistema, which claude, salida esperada con número de versión.

Qué es:

Claude Code lanza actualizaciones frecuentes con nuevos modelos y features. El mismo comando de instalación con npm update -g actualiza.

Por qué aprender:

Las versiones antiguas no son compatibles con los modelos nuevos. La actualización toma 30 segundos y trae mejoras importantes.

Conceptos clave:

npm update -g @anthropic-ai/claude-code, revisar el changelog en GitHub, raros cambios incompatibles.

Qué es:

Claude Code se ejecuta de forma nativa en macOS y Linux. En Windows, usa WSL2 (Windows Subsystem for Linux) para una mejor compatibilidad.

Por qué aprender:

Cada OS tiene particularidades de permisos y PATH distintas. Conocer las diferencias evita horas de frustración.

Conceptos clave:

WSL2 en Windows, Homebrew en macOS para Node.js, distribuciones de Linux recomendadas (Ubuntu 22+).

Qué es:

Los 5 errores más frecuentes: EACCES (permisos de npm), command not found (PATH), ENOENT (versión antigua de Node), network timeout y conflicto de versión.

Por qué aprender:

Los errores de instalación bloquean al 30% de los principiantes. Tener presente el diagnóstico permite resolverlos en minutos.

Conceptos clave:

sudo npm install -g (solución EACCES), nvm para varias versiones de Node, verificar la caché de npm con npm cache clean --force.

🔑 Autenticación y primer uso

Inicio de sesión, API key vs suscripción, el prompt interactivo, los primeros comandos reales y cómo salir/retomar la sesión.

Qué es:

Escribir claude en la terminal abre el REPL interactivo. En la primera ejecución, redirige a la autenticación.

Por qué aprender:

Entender el flujo del primer inicio evita confusiones con los prompts de inicio de sesión y el terminal interactivo.

Conceptos clave:

REPL (Read-Eval-Print Loop), terminal interactiva, flujo automático de onboarding.

Qué es:

Claude Code se autentica mediante browser OAuth con tu cuenta de Anthropic o mediante una API key. Las credenciales se guardan en ~/.claude/.

Por qué aprender:

Elegir entre una cuenta y una API key determina la facturación, los límites y el modelo disponible.

Conceptos clave:

OAuth2 browser flow, carpeta ~/.claude/, triggers, scripts — y el caso real

Qué es:

API key = pagas por uso (tokens). Claude Max = suscripción mensual con un límite generoso. Para un uso intensivo, la suscripción suele convenir más.

Por qué aprender:

Una elección equivocada puede generar costos inesperados o limitar proyectos que necesitan muchas llamadas diarias.

Conceptos clave:

Precios de tokens, límites de tasa, Claude Pro vs Max, variable de entorno ANTHROPIC_API_KEY.

Qué es:

El prompt > acepta lenguaje natural, comandos slash (/help, /clear) y referencias a archivos con @.

Por qué aprender:

Dominar los atajos del REPL multiplica la productividad — sin tener que reescribir el contexto en cada mensaje.

Conceptos clave:

Comandos /help, /clear, /status, referencias a archivos con @, texto multilínea con Enter vs. Shift+Enter.

Qué es:

Pedirle a Claude que cree un archivo, lea un proyecto y explique código existente: las primeras tareas prácticas.

Por qué aprender:

Ponerse manos a la obra de inmediato consolida el aprendizaje y desmitifica el uso de la herramienta.

Conceptos clave:

Prompt de tarea, confirmación de acción, diferencia entre lectura (segura) y escritura (requiere permiso).

Qué es:

Salir con Ctrl+C o /exit. Retoma el contexto anterior con claude --resume o abriendo el mismo directorio.

Por qué aprender:

Las sesiones largas son normales en proyectos reales. Saber retomarlas sin perder contexto es esencial.

Conceptos clave:

Contexto guardado en el directorio, .claude/ local, claude --resume, historial de conversaciones.

🛠️ Configuración: settings.json y permisos

Archivo settings.json de usuario vs. proyecto, sistema de permisos allow/ask/deny, qué habilitar de forma segura y CLAUDE.md básico.

Qué es:

Archivo JSON que controla los permisos, las herramientas, los hooks y los comportamientos de Claude Code. Ubicado en ~/.claude/settings.json (global) o .claude/settings.json (proyecto).

Por qué aprender:

Si no conoces settings.json, aceptas todos los valores predeterminados y recibes solicitudes de permiso para cada acción trivial.

Conceptos clave:

Jerarquía user > project, clave permissions, tools, merge vs. override.

Qué es:

Cada herramienta se puede configurar con allow (ejecutar sin preguntar), ask (pedir confirmación) o deny (bloquear).

Por qué aprender:

Los permisos incorrectos bloquean el workflow o exponen operaciones destructivas. El equilibrio adecuado es productivo y seguro.

Conceptos clave:

Clave allow lista patrones glob, alcance por herramienta (Bash, Read, Write, Edit), override por proyecto.

Qué es:

Reglas generales: leer es seguro (allow), escribir dentro del proyecto está bien, los comandos externos del sistema requieren atención y delete/drop requiere ask.

Por qué aprender:

Permitir todo (allow *) es peligroso en máquinas de producción. Permitir muy poco vuelve inútil la herramienta.

Conceptos clave:

Principio del mínimo privilegio, glob src/** para limitar el alcance, deny para comandos destructivos.

Qué es:

Modos predefinidos: default (pide confirmación para todo), --dangerously-skip-permissions (sin confirmación — solo desarrollo local), modo headless para CI/CD.

Por qué aprender:

En pipelines automatizados necesitas un modo no interactivo. En producción, nunca uses dangerously-skip.

Conceptos clave:

Flag --print para la salida no interactiva, variables de entorno para CI, claude --no-tty.

Qué es:

Archivo Markdown que Claude lee automáticamente en cada sesión. Es el "briefing" del proyecto: contexto, convenciones y comandos especiales.

Por qué aprender:

Sin CLAUDE.md, repites el contexto en cada sesión. Con él, Claude ya conoce el stack, el estilo y las reglas del proyecto.

Conceptos clave:

Posición ./CLAUDE.md o ~/.claude/CLAUDE.md, resumido automático, CLAUDE.md como memoria externa.

Qué es:

Configuración global (~/.claude/settings.json) se aplican a todos los proyectos. Los ajustes del proyecto (.claude/settings.json) se aplican a ese repo.

Por qué aprender:

Configurar correctamente la jerarquía evita conflictos entre proyectos personales y profesionales.

Conceptos clave:

Fusionar objetos JSON, precedencia project > user, versionar .claude/settings.json en el git del proyecto.

🔌 MCP y tu primer proyecto

Model Context Protocol: conecta servidores MCP y herramientas externas, crea y abre un proyecto real de principio a fin.

Qué es:

Model Context Protocol (MCP) es un estándar abierto para conectar Claude con herramientas externas: bases de datos, APIs, sistemas de archivos, servicios en la nube.

Por qué aprender:

Con MCP, Claude deja de ser un chatbot y se convierte en un agente que accede a datos reales de tu entorno.

Conceptos clave:

Servidor MCP, cliente de Claude Code, JSON-RPC, herramientas expuestas mediante MCP, repositorio oficial de servidores.

Qué es:

Agregar un servidor MCP a settings.json en la clave mcpServers. Claude se inicializa y expone las herramientas automáticamente.

Por qué aprender:

Conectar un MCP lleva 2 minutos. Sin este conocimiento, solo usas las herramientas nativas de Claude.

Conceptos clave:

Clave mcpServers en el JSON, command e args, verificar con /mcp en el REPL.

Qué es:

Servidores MCP disponibles: filesystem, GitHub, PostgreSQL, Slack, Google Drive, Puppeteer (browser), SQLite y decenas más.

Por qué aprender:

Cada MCP amplía drásticamente lo que Claude puede hacer. GitHub MCP + Claude = revisión de código automatizada.

Conceptos clave:

Repositorio modelcontextprotocol/servers, MCP oficiales vs. comunitarios, seguridad de servidores de terceros.

Qué es:

Abrir Claude Code en un directorio existente o crear un proyecto desde cero con estructura de archivos, CLAUDE.md y configuración inicial.

Por qué aprender:

Empezar un proyecto correctamente (con CLAUDE.md y settings) garantiza la consistencia durante todo el desarrollo.

Conceptos clave:

cd meu-projeto && claude, estructura de directorios recomendada, /init para generar CLAUDE.md automáticamente.

Qué es:

Crear un proyecto, escribir CLAUDE.md, realizar una tarea real (p. ej., crear una API REST), revisar los cambios y hacer commit, todo con Claude como guía.

Por qué aprender:

Ver el ciclo completo (intención → código → revisión → commit) consolida el modelo mental de uso de Claude Code.

Conceptos clave:

Bucle de desarrollo, diff visual, confirmación de cambios, integración con git, resultado de tareas complejas.

Qué es:

Con la instalación, la autenticación, los settings y MCP configurados, estás listo para explorar Skills (T3), Automatización (T4) y Proyectos reales (T5).

Por qué aprender:

La configuración es la base. Todo lo que viene después depende de que el entorno esté bien configurado.

Conceptos clave:

Skills personalizadas, hooks de automatización, worktrees, proyectos con varios archivos, CI/CD con Claude.
