🌐 Qué es Model Context Protocol (MCP)

MCP es un estándar abierto creado por Anthropic para conectar modelos de lenguaje con herramientas externas. Piensa en él como un "enchufe universal": cualquier herramienta que implemente el protocolo puede conectarse a Claude Code.

🔌 Por qué MCP lo cambia todo

Antes del MCP, Claude Code solo accedía a lo que estaba en el sistema de archivos local. Con MCP, puede:

  • →Consultar una base de datos PostgreSQL para entender el esquema antes de escribir código
  • →Leer issues y PRs de GitHub para tener contexto de una tarea
  • →Navegar por páginas web para investigar documentación
  • →Envía mensajes en Slack al finalizar una tarea automatizada
2

🔗 Configurando servidores MCP

Los servidores MCP se configuran en settings.json en la clave mcpServers. Cada servidor necesita un comando para inicializar y, opcionalmente, argumentos y variables de entorno.

Configuración de servidores MCP en settings.json

{
  "mcpServers": {

    // Servidor filesystem (oficial Anthropic)
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projetos"]
    },

    // Servidor GitHub
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "ghp_..."
      }
    },

    // Servidor PostgreSQL
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_URL": "postgresql://user:pass@localhost/db"
      }
    }
  }
}

Elige el servidor MCP

Buscar en github.com/modelcontextprotocol/servers

# Servidores oficiais disponíveis:
@modelcontextprotocol/server-filesystem
@modelcontextprotocol/server-github
@modelcontextprotocol/server-postgres

Agregar a settings.json

En la clave mcpServers del archivo de configuración

# Editar settings.json
nano ~/.claude/settings.json
# ou via /config no REPL

Reiniciar y verificar

Claude Code inicia los servidores en la próxima sesión

claude
# No REPL verificar servidores ativos:
/mcp
# Output esperado:
✓ filesystem: connected
✓ github: connected

🛠️ Ecosistema MCP: herramientas populares

El repositorio oficial ya tiene decenas de servidores. La comunidad crece rápido: cada semana aparecen nuevos servidores.

📁 Sistema de archivos

Acceso al sistema de archivos más allá del directorio actual

Útil para: monorepos, acceso entre proyectos

🐙 GitHub

Leer/crear issues, PRs, comentarios y commits

Útil para: revisión automática de código, clasificación de issues

🐘 PostgreSQL / SQLite

Consultas SQL, explorar el esquema, analizar datos

Útil para: generar migrations, depurar queries

🤖 Puppeteer

Navegar por la web, tomar capturas de pantalla e interactuar con páginas

Útil para: scraping, pruebas E2E, investigación de documentación

💬 Slack

Leer el historial de canales y enviar mensajes

Útil para: informes automáticos, notificaciones

🗺️ Google Maps / APIs

Servidores comunitarios para APIs externas

Útil para: proyectos con integración de terceros

📁 Crear y abrir un proyecto

Claude Code funciona en el contexto de directorio actual. Abrir el proyecto correcto es el paso cero antes de cualquier tarea.

Abrir un proyecto existente

# Navegar para o projeto e iniciar Claude Code
cd ~/projetos/meu-app
claude

# Claude imediatamente entende o contexto do diretório
# Lê package.json, CLAUDE.md, .claude/settings.json

# Gerar CLAUDE.md se não existir
# Dentro do REPL:
/init
# Claude analisa o projeto e gera rascunho do CLAUDE.md

Crear un proyecto desde cero

# Criar estrutura de projeto
mkdir ~/projetos/novo-projeto
cd ~/projetos/novo-projeto
git init

# Criar settings de projeto
mkdir .claude
cat > .claude/settings.json <<EOF
{
  "permissions": {
    "allow": ["Read(**)", "Write(**)", "Edit(**)", "Bash(npm *)"]
  }
}
EOF

# Iniciar Claude Code e gerar CLAUDE.md
claude
> /init
> Crie um projeto Node.js + TypeScript com estrutura básica

💡 Estructura recomendada para proyectos nuevos

meu-projeto/
├── .claude/
│   └── settings.json    ← permissões do projeto (versionar)
├── CLAUDE.md             ← instruções para o Claude (versionar)
├── src/                  ← código-fonte
├── tests/                ← testes
├── .gitignore
└── package.json

🔄 Primer flujo real: de cero al commit

Mira el ciclo completo de desarrollo con Claude Code. Este ejemplo crea una API REST simple desde cero, con pruebas, y hace el primer commit.

1

Definir el alcance

> Crie uma API REST em Express + TypeScript com um endpoint GET /health
  que retorna { status: "ok", timestamp: ISO8601 }. Inclua um teste
  básico com Vitest.
2

Claude crea los archivos (con confirmación)

# Claude mostra o plano e pede aprovação:
Vou criar: src/app.ts, src/routes/health.ts,
           tests/health.test.ts, package.json
Continuar? [y/n] y
3

Ejecutar pruebas

> Instale as dependências e rode os testes

# Claude executa:
npm install
npm test
✓ health endpoint returns 200  (3ms)
4

Revisar y hacer commit

> Revise os arquivos criados e faça um commit inicial

# Claude mostra diff → você revisa → aprova
git add .
git commit -m "feat: adicionar endpoint GET /health"
