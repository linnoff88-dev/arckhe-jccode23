🤖 Subagents: delegar tareas

Aprende a delegar tareas complejas a subagentes paralelos y multiplica la capacidad de Claude Code sin aumentar el tiempo de espera.

Qué es

Un subagent es una instancia de Claude Code que el agente principal inicia para ejecutar una tarea específica de forma aislada. Recibe un prompt bien definido, trabaja de forma independiente y devuelve el resultado resumido al orquestador.

Por qué aprender

Con subagents paralelizas el trabajo: mientras uno investiga la documentación, otro escribe pruebas y un tercero revisa el código. Lo que tomaría horas en serie ocurre en minutos.

Conceptos clave

  • • Aislamiento: cada subagent tiene su propio contexto
  • • Retorno resumido: solo vuelve el resultado al principal
  • • Herramienta Task: mecanismo interno de lanzamiento

Qué es

No todas las tareas merecen un subagent. Delegar tiene sentido cuando la tarea es independiente, tiene un alcance claro y el orquestador puede consumir el resultado de forma atómica.

Por qué aprender

Delegar de forma incorrecta aumenta el costo sin aportar beneficios. Saber cuándo delegar marca la diferencia entre una automatización eficiente y un exceso de trabajo innecesario.

Conceptos clave

  • • Tareas independientes: no necesitan contexto compartido
  • • Búsquedas amplias: explorar varias fuentes al mismo tiempo
  • • Alcance atómico: el resultado cabe en pocas líneas

Qué es

Fan-out es el patrón en el que un orquestador activa N subagentes simultáneamente, cada uno resolviendo una parte del problema. Los resultados se recopilan e integran al final.

Por qué aprender

Fan-out es el patrón de automatización más potente con Claude Code. Las investigaciones que tomarían 1 hora en serie se completan en minutos al paralelizarlas con 4-8 subagentes.

Conceptos clave

  • • Orquestador: agente principal que distribuye tareas
  • • Workers: subagentes que ejecutan en paralelo
  • • Agregación: el orquestador integra los resultados

Qué es

Claude Code admite distintos perfiles de subagent: el tipo Explore se enfoca en leer y analizar (sin escribir); General puede ejecutar cualquier herramienta. La elección determina los permisos y el riesgo.

Por qué aprender

Usar el tipo incorrecto de subagent puede crear riesgos de seguridad (un agente de investigación con permiso de escritura) o limitar la funcionalidad (un agente de codificación sin permiso de exec).

Conceptos clave

  • • Explore: solo lectura — ideal para investigación y análisis
  • • General: acceso completo a las herramientas
  • • Principio de mínimo privilegio: usa siempre el tipo mínimo necesario

Qué es

El resultado de un subagent vuelve al orquestador como texto comprimido: un resumen de lo que se hizo, no el log completo de ejecución. Esto preserva el contexto del agente principal.

Por qué aprender

Entender cómo vuelve el resultado ayuda a formular mejores prompts: especificar el formato de salida esperado (JSON, markdown, lista) garantiza que el orquestador consuma el resultado sin tener que rehacer el trabajo.

Conceptos clave

  • • Retorno atómico: un mensaje con el resultado consolidado
  • • Formato explícito: indica al subagent cómo dar formato
  • • Presión sobre el contexto: los resultados largos consumen tokens del orquestador

Qué es

Cada subagent consume tokens: el prompt de instrucción + la ejecución + el resultado. Con varios subagents en paralelo, el costo puede escalar rápidamente si no hay control.

Por qué aprender

Una automatización mal planificada puede costar más que el trabajo manual equivalente. Calcular el ROI antes de implementar subagents es una práctica profesional esencial.

Conceptos clave

  • • Costo por subagent: prompt + ejecución + salida
  • • Prompt caching: reutilizar el contexto reduce el costo hasta en un 90%
  • • ROI: velocidad ganada × valor del tiempo frente al costo de la API

🪝 Hooks: automatizar el harness

Configura hooks de eventos para automatizar acciones antes y después de cada herramienta: lint, seguridad e inyección de contexto sin tocar el código del agente.

Qué es

Los hooks son scripts externos que ejecuta el harness en momentos específicos del ciclo de vida del agente: antes de una herramienta (PreToolUse), después (PostToolUse), al iniciar una sesión (SessionStart) o al detenerse (Stop).

Por qué aprender

Con hooks agregas comportamiento sin modificar el prompt ni el código del agente. Es la forma más limpia de imponer políticas: lint siempre se ejecuta, los comandos prohibidos se bloquean automáticamente.

Conceptos clave

  • • PreToolUse: antes de ejecutar cualquier herramienta
  • • PostToolUse: después de que la herramienta devuelva el resultado
  • • SessionStart: al abrir una nueva sesión
  • • Stop: al cerrar el agente

Qué es

Los hooks se configuran en la clave hooks del archivo settings.json (global en ~/.claude/ o local en .claude/). Cada hook es un objeto con evento, matcher de herramienta y comando shell.

Por qué aprender

La configuración declarativa en settings.json permite versionar los hooks junto con el proyecto. Equipos enteros heredan las políticas automáticamente, sin onboarding manual.

Conceptos clave

  • • Global: ~/.claude/settings.json — se aplica a todos los proyectos
  • • Local: .claude/settings.json — específico del proyecto
  • • matcher: filtra por nombre de herramienta (glob)

Qué es

Un hook PreToolUse puede devolver un código de salida distinto de cero para cancelar la herramienta antes de ejecutarla. Esto permite crear listas negras de comandos — por ejemplo, bloquear git push --force.

Por qué aprender

Comandos destructivos como rm -rf o un force push en main pueden causar daños irreversibles. Un hook de bloqueo es la última línea de defensa.

Conceptos clave

  • • Exit 1: señala un bloqueo al harness
  • • Mensaje de stderr: explica el motivo al agente
  • • Patrones regex: detectar comandos prohibidos

Qué es

Un hook PostToolUse puede ejecutar lint o formato automáticamente cada vez que el agente guarda un archivo. El output de lint se inyecta de nuevo en el contexto, lo que permite que el agente corrija los errores en la siguiente iteración.

Por qué aprender

Sin lint automático, el agente puede generar código con errores de formato que solo aparecen en CI. Con el hook, cada guardado produce código limpio: un ciclo de retroalimentación instantáneo.

Conceptos clave

  • • Trigger: PostToolUse en Write/Edit
  • • Output injection: el stdout del hook se incorpora al contexto
  • • Ejemplos: eslint, prettier, ruff, black

Qué es

El hook SessionStart se ejecuta cuando comienza una nueva sesión. Su salida se inyecta como mensaje inicial en el contexto: es ideal para cargar metadatos del proyecto, la rama actual, variables de entorno o recuerdos relevantes.

Por qué aprender

En lugar de repetir el estado del proyecto en cada nuevo prompt, SessionStart lo inyecta automáticamente. El agente empieza cada sesión con el contexto necesario: menos tokens consumidos y más enfoque en el trabajo.

Conceptos clave

  • • git status, branch, último commit
  • • Tareas pendientes del proyecto
  • • Variables de entorno relevantes

Qué es

De forma predeterminada, si un hook falla (timeout, error de script), el harness continúa la ejecución: comportamiento "fail-open". En hooks de seguridad críticos, puedes configurar fail-closed para detenerlo todo.

Por qué aprender

Confiar demasiado en fail-open puede dejar brechas de seguridad. Entender el modelo de fallos de los hooks permite diseñar sistemas más robustos, donde las políticas críticas nunca se ignoran silenciosamente.

Conceptos clave

  • • Fail-open: un hook con errores no bloquea la ejecución
  • • Tiempo de espera: se cancelan los hooks lentos
  • • Principio: los hooks de auditoría son fail-open; los de seguridad, fail-closed

⌨️ Slash commands y workflows

Crea atajos reutilizables y pipelines deterministas que orquestan múltiples agentes en secuencia o en paralelo con un solo comando.

Qué es

Los comandos slash son atajos de texto que se expanden en prompts completos. Al escribir /review en Claude Code, el harness expande a un prompt de revisión de código preconfigurado.

Por qué aprender

En lugar de reescribir el mismo prompt largo una y otra vez, escribes 3 caracteres y obtienes total consistencia. Equipos enteros usan los mismos patrones sin memorizar instrucciones complejas.

Conceptos clave

  • • Expansión: /comando → prompt completo
  • • Argumentos: /comando arg1 arg2
  • • Alcance: global o por proyecto

Qué es

Los comandos personalizados se definen como archivos .md dentro de la carpeta .claude/commands/. El nombre del archivo se convierte en el comando. El contenido es el prompt que se expandirá.

Por qué aprender

Cada proyecto tiene necesidades únicas. Un proyecto React puede tener /component, vale la pena crear un comando slash. Si vas a hacer /migrate. Personalizar es parte de la configuración profesional.

Conceptos clave

  • • Local: .claude/commands/meu-cmd.md
  • • Global: ~/.claude/commands/meu-cmd.md
  • • Variables: $ARGUMENTS, $FILE, $SELECTION

Qué es

Un workflow determinista es una secuencia predefinida de pasos — cada paso puede ser un agente, un comando shell o una transformación de datos. El resultado de un paso alimenta el siguiente, sin variaciones aleatorias.

Por qué aprender

Cuando el proceso debe ser auditable y reproducible (CI/CD, releases, revisiones obligatorias), la determinación vale más que la creatividad. Los workflows garantizan que cada paso ocurra siempre.

Conceptos clave

  • • Idempotencia: ejecutarlo 2 veces produce el mismo resultado
  • • Rollback: cada step debe tener un undo definido
  • • Logging: registrar cada step para auditoría

Qué es

Pipeline: pasos encadenados en los que la salida de A es la entrada de B. Paralelo: varios agentes que se ejecutan al mismo tiempo sin depender unos de otros. Muchos workflows combinan ambos patrones.

Por qué aprender

Elegir el patrón equivocado puede duplicar el tiempo de ejecución (cuando debería paralelizarse) o producir resultados inconsistentes (cuando debería serializarse). El diseño del workflow es tan importante como el contenido.

Conceptos clave

  • • Pipeline: dependencia de datos entre steps
  • • Parallel: independencia total entre workers
  • • Barrier: punto de sincronización después del paralelo

Qué es

Los workflows son más adecuados cuando la tarea se repite con frecuencia, involucra varios agentes o necesita auditabilidad. Las tareas únicas y creativas se resuelven mejor con prompts libres.

Por qué aprender

Diseñar workflows demasiado complejos para tareas simples es un desperdicio. Diseñarlos de forma insuficiente para tareas críticas es un riesgo. Saber cuál es el punto justo es la habilidad más valiosa en automatización.

Conceptos clave

  • • Frecuencia: las tareas diarias justifican la inversión
  • • Riesgo: las tareas destructivas necesitan un workflow controlado
  • • Equipo: los estándares compartidos necesitan un workflow

Qué es

Un metaagente (u orquestador de nivel superior) puede invocar workflows completos como subtareas. Esto crea una jerarquía: orquestador → workflow → subagents — cada nivel con responsabilidades bien definidas.

Por qué aprender

En proyectos grandes, un solo agente monolítico se pierde entre tanta complejidad. La jerarquía de orquestadores divide el problema en capas manejables: cada capa está bien probada y se puede reemplazar.

Conceptos clave

  • • Composición: workflows como bloques de construcción
  • • Interfaz: cada workflow tiene inputs y outputs claros
  • • Observabilidad: los logs se propagan por la jerarquía

⏰ Cron y tareas recurrentes

Programa agentes para que se ejecuten en intervalos definidos: revisiones diarias, informes automáticos y monitoreo continuo sin intervención humana.

Qué es

Cron permite programar tareas para que se ejecuten en horarios específicos (diariamente, semanalmente, cada hora). Claude Code se integra con cron mediante la skill /schedule para crear rutinas de agente.

Por qué aprender

Las tareas recurrentes son la mayor pérdida de tiempo para los desarrolladores. Code review diario, actualización de dependencias, informe de métricas — todo puede ejecutarse sin intervención humana.

Conceptos clave

  • • Sintaxis cron: minuto hora día mes día de la semana
  • • /schedule: skill nativa de Claude Code
  • • Trigger: evento de tiempo o evento del sistema

Qué es

El comando /loop repite una tarea a intervalos definidos mientras la sesión está activa. Es ideal para consultar el estado, monitorear una compilación u observar continuamente un sistema.

Por qué aprender

/loop es más simple que cron para tareas de corta duración. No requiere configurar infraestructura: se ejecuta en la sesión actual y se detiene cuando cierras la terminal.

Conceptos clave

  • • /loop 5m /status: ejecuta /status cada 5 minutos
  • • Auto-pace: sin intervalo, el agente decide el ritmo
  • • Cancelación: Ctrl+C cierra el bucle

Qué es

Los agentes remotos se ejecutan en la infraestructura de Claude sin necesidad de tener una terminal local abierta. Se activan por eventos (webhook, cron) y funcionan de forma completamente autónoma.

Por qué aprender

Los agentes remotos son la frontera entre la automatización local y la automatización en producción. Cuando no quieres (ni puedes) tener una laptop encendida las 24 h para ejecutar tareas, los agentes remotos son la solución.

Conceptos clave

  • • RemoteTrigger: inicia un agente sin sesión local
  • • Resultado asíncrono: notificación cuando termina
  • • Permisos: definidos en settings.json antes del deploy

Qué es

Un agente de revisión diaria se ejecuta mediante cron todos los días a las 9h, analiza el código confirmado el día anterior, genera un informe de calidad y lo envía como notificación o lo guarda en un archivo.

Por qué aprender

La revisión automática del código no sustituye a la revisión humana, pero detecta el 80% de los errores mecánicos antes de la revisión humana. Quien revisa se enfoca en lo que importa: arquitectura y lógica de negocio.

Conceptos clave

  • • git log --since=yesterday: obtiene los commits del día
  • • /code-review: skill nativa de Claude Code
  • • Output: archivo .md o webhook para Slack/Discord

Qué es

Los agentes asíncronos no devuelven resultados de inmediato. El output puede recopilarse mediante PushNotification (webhook), un archivo generado o polling con Monitor, según el mecanismo de entrega configurado.

Por qué aprender

La automatización sin observabilidad es automatización a ciegas. Saber dónde y cómo llega el resultado es fundamental para confiar en la automatización y para depurar cuando algo sale mal a las 3 de la mañana.

Conceptos clave

  • • PushNotification: webhook con el resultado
  • • Monitor: flujo de eventos en tiempo real
  • • Archivo: ruta configurable de output

Qué es

Los agentes recurrentes acumulan costos con el tiempo. La idempotencia garantiza que ejecutar el agente dos veces produzca el mismo resultado, algo crucial cuando los fallos llevan a volver a ejecutarlo.

Por qué aprender

Una tarea cron que falla y se vuelve a ejecutar 5× puede crear 5 PR idénticos o cobrar 5× el costo esperado. La idempotencia no es un detalle — es un requisito de producción.

Conceptos clave

  • • Verificar antes de actuar: comprobar si la tarea ya se hizo
  • • Lock file: evitar ejecuciones simultáneas
  • • Budget alerts: notificar cuando el costo supera el umbral
