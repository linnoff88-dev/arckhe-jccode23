🤖 Subagents: delegar tareas

Aprende a delegar tareas complejas a instancias paralelas de Claude Code y multiplica tu capacidad sin aumentar el tiempo de espera.

🧠 Qué es un subagent

Uno subagent es una instancia independiente de Claude Code que el agente principal (orquestador) inicia para ejecutar una tarea específica. Recibe un prompt bien delimitado, trabaja con sus propias herramientas y devuelve un resultado resumido.

El orquestador usa la herramienta interna Task para crear subagents. Cada Task está aislada: tiene su propio historial de conversación, contexto de archivos y permisos configurados.

💡 Concepto central

El subagente no comparte memoria con el orquestador. Solo sabe lo que está en el prompt que recibió. Esto es una feature: el aislamiento garantiza que un subagent no contamine el contexto de otro.

Ciclo de vida de un subagent

1

El orquestador formula la tarea

Define el prompt con un alcance claro, el formato de salida esperado y los permisos necesarios

2

Harness inicia la instancia

Se crea una nueva sesión aislada con el prompt como contexto inicial

3

El Subagent ejecuta con herramientas

Usa Bash, Read, WebSearch y otras herramientas según sea necesario

4

El resultado vuelve al orquestador

Texto comprimido con el resultado: no el registro completo, solo la respuesta

🎯 Cuándo delegar a un subagent

✓ Delegar CUÁNDO

  • ✓ La tarea tiene un alcance bien definido y un resultado atómico
  • ✓ Puede ejecutarse en paralelo con otras tareas
  • ✓ Investigación amplia (múltiples fuentes, múltiples archivos)
  • ✓ Tarea repetida N veces con distintos inputs
  • ✓ Aislamiento de riesgos (probar código peligroso)

✗ NO delegues CUANDO

  • ✗ La tarea requiere acceso al historial del orquestador
  • ✗ El resultado es trivial (2-3 líneas de código)
  • ✗ Los Subagents necesitan comunicarse entre sí en tiempo real
  • ✗ El costo de los tokens supera el beneficio de velocidad
  • ✗ La tarea requiere aprobación humana durante el proceso

💡 Consejo práctico

El criterio más rápido: ¿puedes describir la tarea en 1-2 frases con entradas y salidas claras? Si es así, es candidato a subagent. Si necesita párrafos de contexto, ejecútalo directamente en el orquestador.

⚡ Fan-out: el patrón más poderoso

Fan-out ocurre cuando un orquestador activa N subagentes simultáneamente, cada uno resuelve una parte del problema. El orquestador queda bloqueado esperando a que todos terminen y luego agrega los resultados.

Una investigación que visitaría 8 fuentes en serie (8 × 30s = 4 minutos) se convierte en 8 subagents en paralelo (~30 segundos). Velocidad 8× con el mismo costo total.

// Ejemplo de prompt para un orquestador con fan-out
Tú eres quien coordina. Usa la herramienta Task para crear
4 subagents en PARALELO:

Task 1: Busca la documentación oficial de Claude Code sobre hooks.
         Devuelve: lista de eventos disponibles con una descripción.

Task 2: Lee los archivos .claude/settings.json del proyecto.
         Devuelve: estructura actual de la configuración.

Task 3: Busca ejemplos de hooks en repositorios públicos.
         Devuelve: 3 ejemplos prácticos con código.

Task 4: Analiza el código en src/ para identificar
         oportunidades de automatización con hooks.
         Devuelve: lista priorizada de mejoras.

// Espera a que TODOS terminen y después integra los resultados.

📊 Ahorro de tiempo real

Serie (4 tareas × 3 min) 12 min
Fan-out paralelo (4 agentes) ~3 min
Beneficio 4× más rápido

⚠️ Límite práctico

La velocidad aumenta con N subagents, pero el costo también. Para tareas de 1-2 minutos, el fan-out con 4-8 agentes es el punto óptimo. Con más de 10 agentes, el costo de coordinación reduce el rendimiento.

🔬 Tipos de subagent: Explore vs General

🔍 Tipo Explore

Modo de lectura — acceso solo a herramientas de observación (Read, Bash de solo lectura, WebSearch). No puede crear ni modificar archivos.

  • →Ideal para investigar, analizar un codebase y buscar en la documentación
  • →Más seguro — sin riesgo de modificaciones accidentales
  • →Más barato — contexto más pequeño, menos herramientas

⚙️ Tipo General

Acceso completo a las herramientas — puede leer, escribir, ejecutar comandos e interactuar con API externas.

  • →Ideal para implementar, probar y hacer deploy
  • →Requiere permisos configurados cuidadosamente
  • →Úsalo cuando necesites actuar, no solo analizar

🚨 Principio del mínimo privilegio

Usa siempre el tipo más restrictivo que permita la tarea. Un subagent de investigación con permiso de escritura es un riesgo innecesario: si el modelo «alucina» una instrucción, podría modificar archivos por error.

💰 Resultado, costo y ROI

Cómo vuelve el resultado

El resultado de un subagent llega al orquestador como texto puro — un resumen consolidado de lo que se encontró/hizo. El orquestador no recibe el registro de herramientas, solo la respuesta final.

Para garantizar que el resultado se pueda consumir, especifica el formato de salida en el prompt: Retorne: lista de bullets, Retorne: JSON com campos X e Y, etc.

// Estimación de costo por subagent (Claude Sonnet)
Prompt do orquestrador:   ~500 tokens  ($0.003)
Execução do subagent:     ~2000 tokens ($0.012)
Output para orquestrador: ~300 tokens  ($0.002)
                           ──────────────────────
Total por subagent:        ~$0.017

// Com prompt caching (se CLAUDE.md ou contexto fixo):
Custo cache hit: ~$0.002 (10× mais barato)

// ROI: 1h de trabalho humano = $50-100
// 100 subagents = $1.70 → 30× mais barato que humano

💡 Cálculo rápido del ROI

Compara: tiempo ahorrado × valor de tu tiempo vs costo de la API. Si ahorras 1h ($50) y la automatización cuesta $0.50, el ROI es de 100×. Esto aplica a cualquier tarea que haces más de una vez por semana.

✅ Buenas prácticas al usar subagents

✓ Qué HACER

  • ✓ Especificar el formato de salida en el prompt
  • ✓ Usar el tipo más restringido posible
  • ✓ Limitar el alcance: una responsabilidad por subagent
  • ✓ Activar el almacenamiento en caché de prompts para contextos repetidos

✗ Qué EVITAR

  • ✗ Subagents que dependen unos de otros en tiempo real
  • ✗ Pasar todo el historial del orquestador como contexto
  • ✗ Subagents con permiso de escritura en la base de datos de producción
  • ✗ Más de 10 subagents paralelos sin estimar el costo antes
