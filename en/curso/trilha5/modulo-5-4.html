2 ⚙️ scripts/aggregate.ts — the heart of the system

The most important file in ClaudeOS isn't a React component — it's a TypeScript script that runs outside the browser. It reads heterogeneous sources and produces a single JSON file consumed by the dashboard.

✓ Elegant pattern

  • • Promise.all for parallel I/O

  • • Generation timestamp included

💡

The “script → JSON → UI” pattern

Separating data collection from presentation is one of the most resilient architectures for personal projects. You can rebuild the dashboard from scratch without losing data. The pipeline can run on cron without the UI existing.

4 📜 ClaudeOS CLAUDE.md — real example

ClaudeOS's CLAUDE.md is an example of production-level instructions. Each rule has a clear reason for existing.

CLAUDE.md — ClaudeOS (Hermes) 
# ClaudeOS (Hermes) — Instruções do agente

## Saudação de onboarding
Bem-vindo ao ClaudeOS! Você está trabalhando no dashboard
pessoal de IA. Antes de qualquer task, leia este arquivo.

## O que é este projeto
Dashboard read-only que consolida dados de Claude Code,
Obsidian, OpenRouter e Pinecone para visualização pessoal.
Stack: Bun + React 19 + TanStack Query + Vite + Tailwind 4
Deploy: Cloudflare Pages (wrangler)

## Regras OBRIGATÓRIAS

### Privacidade
- NUNCA ler ou escrever diretamente em ~/.claude/
  → Dados chegam via scripts/aggregate.ts e src/data/live-data.json
- NUNCA enviar dados do usuário para serviços externos
- Anonimização LIGADA — remove PII de outputs
- Sem telemetria — sem analytics, sem tracking

### Arquitetura
- Dashboard é READ-ONLY — NUNCA modificar fontes de dados
- Código novo vai em src/ — scripts de dados vão em scripts/
- Não criar arquivos na raiz do projeto

### Segurança
- API keys SEMPRE via variáveis de ambiente (.env)
- .env está no .gitignore — nunca commit

## Estrutura do projeto
src/
  components/   → UI React
  data/         → live-data.json (gerado, não editado)
scripts/
  aggregate.ts  → coleta dados das fontes
  setup.ts      → setup inicial (roda uma vez)

🔍 Why Each Rule Exists

Never read ~/.claude directly: prevents inadvertent access to private conversations
Read-only enforcement: prevents bugs that corrupt data sources
No telemetry: personal project — no data leaves the device

🧩 Reusable pattern

• Onboarding greeting = immediate context

• Rules by category (privacy, architecture, security)

• Inline justification for each critical constraint

• Folder map with an explicit purpose
